# Builder brief: 3.5b Open the dashboard from the portal (one sign-in, account-scoped)

You are a builder session for the IntoFocus AI client portal. The PM session wrote this brief. Work only on what is below.

## Goal (user approved 2026-11-18)
A client signed in to the portal opens "IntoFocus AI Consensus Control" from Dashboards and lands in the real dashboard (the ifai-dashboard app) without signing in again, seeing only their own account's brands. The dashboard decides who someone is and which account they may see from the portal's accounts (`public.organizations`, `public.organization_memberships`) and the portal's entitlement check, not from the old `command.*` org tables. Every data read happens as the signed-in user (no anon reads of client data).

## Scope
1. Sign-in: the dashboard reads the user's accounts from `public.organization_memberships` / `public.organizations` (active account chosen like the portal; staff via `private.is_staff()` through a public wrapper). Keep the `command.*` path behind a flag only as long as needed for current internal users, and list who still depends on it (1.2 retires it later).
2. Entitlement: on every dashboard load call `public.open_module(org, 'consensus_control', reason)`; show the portal's messages for blocked states (same copy as `docs/dashboards.md`); staff without membership must give a reason (reuse the portal's flow: the reason passed from the portal or asked in the dashboard).
3. Account scope: the dashboard shows only clients (brands) mapped to the active account (sandbox `client.organization_id`, and `client_schema_org` for FMIC and Ledlenser). Never take an account or client id from the URL as authority; a URL value is only a selector re-checked server side.
4. Signed-in reads: every query that reads client data uses the signed-in user's session (server client with cookies, or browser client with the user's session). Remove anon-key reads of client data. List each changed call site.
5. One sign-in: a user signed in to the portal is not asked to sign in again. Preferred: Supabase session cookies shared on the parent domain (portal at app.intofocus.ai; dashboard on a sibling subdomain or path, your recommendation in the PR). Never put access or refresh tokens in a URL or log. If shared cookies need the portal to change how it stores the session, include that change in the portal PR with tests. Document the domain setup for go-live (no hosted changes now).
6. Portal: "Open dashboard" launches the dashboard for the active account; Back to the portal works; full-screen toggle stays.
7. Docs: ifai-dashboard TDD section on auth and access; propose FDD row changes in the PR body (Brian approves); intofocus-portal `docs/dashboards.md`.
